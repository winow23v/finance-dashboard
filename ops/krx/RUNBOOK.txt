Phase 16 KRX history import (304 sessions, 2025-08-22 through 2026-11-20)

This import does not call KRX or modify authentication or API configuration.
It transfers only the two markets' validated daily OHLCV files, including
observed empty market days. It does not transfer quotes, listing metadata,
ledgers, environment files or keys. Ensure the membership display and historical
storage are covered by the operating data rights before transferring the files.

1. Resolve the live cache path from the Fastify process KRX_MEMBER_CACHE_DIR,
   or its configured fallback (.krx-cache/member relative to the deployed
   provider module). If the configured value is relative, resolve it using the
   live process working directory. Determine the Fastify service account.
2. Run the local manifest check, and use the resulting 64-digit source SHA on
   Oracle. Transfer only the matching ohlcv-KOSPI/DAQ-YYYY-MM-DD.json files
   for the stated date range through an approved private channel. Keep them
   outside the Git working tree on Oracle. Re-run verify against that directory.

     node ops/krx/import-history.mjs verify vps-api/.krx-cache
     node import-history.mjs verify "$STAGED_CACHE"

3. As the Fastify service account, compare source and destination. If existing
   files differ, the tool reports filenames and refuses the import. Review the
   cached dates and differences before proceeding, including equivalent files
   that differ only in serialization.

     node import-history.mjs plan "$STAGED_CACHE" "$MEMBER_CACHE"

4. If missing files must be added, make a restricted backup on Oracle before
   apply. Back up the member cache itself, keeping service environment files
   and keys outside the archive. Verify the archive checksum and test extraction
   into an isolated directory. Keep a before and after plan and source digest.

     umask 077
     (cd "$MEMBER_CACHE" &&
       find . -maxdepth 1 -type f \( -name '*.json' -o -name '*.jsonl' \) -print0 |
       tar --null -czf "$BACKUP" -T -)
     sha256sum "$BACKUP" > "$BACKUP.sha256"
     sha256sum -c "$BACKUP.sha256"
     tar -tzf "$BACKUP"

   Use a protected BACKUP path outside MEMBER_CACHE. A cache backup preserves
   the existing data, which may be subject to retention restrictions.
5. Run apply as the account that runs Fastify. The destination already exists.
   Each missing file is linked atomically, and existing files stay untouched
   even if created after the plan. An interrupted import is safely repeatable.

     node import-history.mjs apply "$STAGED_CACHE" "$MEMBER_CACHE" "$SOURCE_SHA256"
     node import-history.mjs plan "$STAGED_CACHE" "$MEMBER_CACHE"

6. Verify each symbol in the approved-member API and UI, plus existing KRX
   overview, exchange rates and US market. The importer and existing history
   reader require no Fastify restart. The normal API release workflow is
   independent of this operation.

Recovery
- Stop further import attempts to avoid changing data during recovery.
- Verify the untouched backup checksum. Restore it into a fresh restricted
  directory and validate file ownership, modes and API readability. Do not
  extract over the live tree. For a full rollback, switch to the restored tree
  in an approved service transition after preserving the current live tree.
- If an import stops early, existing files are preserved. Review the report
  and repeat the plan before re-applying. Review conflicts with an operator
  before replacing any file.

Phase 19-L member collection

- The existing Fastify process runs one in-process collector. No separate service
  or timer is required. Run only one member collector per KRX cache directory.
  Member HTTP reads use the file-backed snapshots and do not dispatch KRX calls.
- Use FINANCE_MEMBER_KRX=1, the existing KRX_API_KEY and the existing
  KRX_MEMBER_CACHE_DIR. Back up that directory and verify that the API service
  account can write to it. Preserve the existing OHLCV history and permissions.
- The collector checks the current trading date at 21:15 KST. It checks the
  previous trading date at 08:10 and 10:10 KST on the next trading day if
  a dataset is still pending. These are collection windows based on the
  incident history. Confirm upstream publication timing from a normal run.
- The 10:10 window also examines up to ten older trading sessions for gaps.
  Automatic recovery handles up to four datasets per trading day after the
  regular collection. It shares backfill.flock and a persistent rolling
  24-hour budget of 300 attempts with the CLI for this cache directory.
  A 429 pauses calls for at least 30 minutes or Retry-After, whichever is
  longer. Both the window reservations and cooldown survive restarts.
- Before validating a release containing the CLI, compare the installed
  /usr/local/bin/finance-dashboard-release with .github/scripts/oracle-release.sh.
  The installed script must explicitly accept and install krx-backfill.mjs.
  Update the root-managed script through the approved administrative process.
  Validate and deploy stage the CLI file without invoking it.
- For a read-only plan, use the API service account and the same KRX_MEMBER_CACHE_DIR
  and KRX_CALENDAR_OVERRIDES settings as the running service:
    node /opt/finance-dashboard/vps-api/krx-backfill.mjs --member --plan 2026-11-23 2026-11-24
  If the service has no cache override, leave KRX_MEMBER_CACHE_DIR unset so both
  use the same application-relative member cache. Confirm the plan reports the
  live cache path. If the service uses a relative override, resolve it against
  the service WorkingDirectory and pass the absolute path to the CLI.
  Use --markets=KOSPI,KOSDAQ or --kinds=trades,index to narrow the plan.
  After separate approval, use --apply instead of --plan with the service's
  credentials and environment. Each invocation processes up to four datasets.
- The included holiday calendar covers 2026. Set KRX_CALENDAR_OVERRIDES to a JSON
  object when an official special close or a new year is announced. The following
  illustrates the format only:
  {"years":[2027],"closed":["2027-01-01"],"regularClose":{"2027-01-04":"15:30"},"afterClose":{"2027-01-04":"20:00"}}
  Include the complete official holiday list before enabling a new year.
  Collection is held for an uncovered year. The regular check never starts
  before 21:15 or 30 minutes after a late official close.
- The after-hours connection check runs at 20:15 or 15 minutes after an
  overridden late close. The check records an unconnected state for each
  venue. It does not call a quote endpoint or write an OHLCV bar.
  Connect a venue-specific provider after verifying feed scope, display
  approval, symbol eligibility and the observation timestamp.
- After approval, deploy the Oracle API and check its scheduled result, the
  existing history and the KRX stock history endpoint before the Pages rollout.
  Watch 429s, cache write failures and aggregate memory and CPU. For rollback,
  restore the previous API and frontend releases. Preserve the cache.

Phase 19-L read-only operational verification (after access is available)

Run on Oracle. These commands read service metadata and selected cache keys.
They never print the process environment, tokens, keys, or cached stock rows.

    service=finance-dashboard-api.service
    systemctl is-active "$service"
    systemctl show "$service" -p MainPID -p WorkingDirectory -p User -p MemoryCurrent -p CPUUsageNSec
    getconf _NPROCESSORS_ONLN
    free -m
    vmstat 1 3
    systemctl list-timers --all --no-pager
    pid=$(systemctl show "$service" -p MainPID --value)
    test "$pid" -gt 1
    runtime=$(sudo readlink "/proc/$pid/exe")
    cwd=$(sudo readlink "/proc/$pid/cwd")
    service_user=$(systemctl show "$service" -p User --value)
    cache=$(sudo "$runtime" - "$pid" "$cwd" <<'NODE'
    const fs = require('node:fs')
    const path = require('node:path')
    const [, , pid, cwd] = process.argv
    const entry = fs.readFileSync('/proc/' + pid + '/environ', 'utf8').split('\0')
      .find(value => value.startsWith('KRX_MEMBER_CACHE_DIR='))
    const configured = entry?.slice('KRX_MEMBER_CACHE_DIR='.length).trim()
    console.log(path.resolve(cwd, configured || '.krx-cache/member'))
    NODE
    )
    printf 'KRX cache: %s\n' "$cache"
    sudo -u "${service_user:-root}" test -r "$cache"
    sudo -u "${service_user:-root}" test -w "$cache"
    sudo -u "${service_user:-root}" test -x "$cache"
    curl -fsS http://127.0.0.1:3000/health
    sudo sha256sum "$cwd/server.mjs" "$cwd/krx-provider.mjs" "$cwd/krx-calendar-provider.mjs"
    sudo "$runtime" - "$cache" <<'NODE'
    const fs = require('node:fs')
    const path = require('node:path')
    const root = process.argv[2]
    for (const name of ['idx-kospi_dd_trd', 'idx-kosdaq_dd_trd', 'sto-stk_bydd_trd',
      'sto-ksq_bydd_trd', 'sto-stk_isu_base_info', 'sto-ksq_isu_base_info',
      'krx-regular-cooldown', 'krx-after-hours-check']) {
      try {
        const value = JSON.parse(fs.readFileSync(path.join(root, name + '.json')))
        console.log(JSON.stringify({ name, date: value.data?.date ?? value.date,
          collectedAt: value.data?.collectedAt, attempt: value.attempt,
          blockedUntil: value.blockedUntil, connectionCheckedAt: value.at }))
      } catch (error) {
        console.log(JSON.stringify({ name, error: error.code ?? 'INVALID_CACHE_JSON' }))
      }
    }
    NODE

    backup="/var/backups/finance-dashboard/krx-$(date -u +%Y%m%dT%H%M%SZ).tar"
