CSP 및 회귀 검증
- vite.config.ts는 프로덕션 HTML의 자산 태그 앞에 CSP를 삽입한다.
  스크립트, 스타일시트, 이미지, 폰트는 동일 출처를 사용한다.
  객체와 프레임 로드는 금지하고 base 및 form 제출은 동일 출처로 제한한다.
  인라인 스크립트와 unsafe-eval은 허용하지 않는다. 기존 차트·히트맵
  레이아웃을 위해 style 속성에만 인라인 스타일 예외를 둔다.
- connect-src는 동일 출처와 빌드에 설정된 HTTPS API 및 Supabase origin으로
  제한한다. 운영 출처는 https://winow.duckdns.org 및
  https://wcrdvyxnuqjlsmparpgj.supabase.co 이다.
  Google 로그인은 Supabase PKCE의 최상위 탐색이다. ECB, FRED, DART,
  ECOS, KOSIS 등 화면 출처 링크도 탐색이며 금융 데이터 요청은 앱 API를
  사용한다. Vite 개발 프록시와 서버 토큰 처리는 기존 설정을 사용한다.
- index.html은 strict-origin-when-cross-origin을 명시한다. Chromium에서
  OAuth 시작 시 Supabase에 origin만 전달되고 PKCE challenge 및
  redirect_to가 유지됨을 확인했다.
- Chromium에서 모의 승인 회원으로 초기 화면, 국내·해외 지수, AAPL 검색,
  종목 상세, RSI·MACD·SMA, 환율 차트, API 성공·실패 흐름, 개인정보처리방침,
  모바일 메뉴를 확인했다. 관찰된 CSP 위반과 페이지 예외는 0건이다.
  실제 Google 계정 승인과 콜백은 다음 승인된 배포 검증에서 확인한다.

자동 점검과 배포 후 확인
- .github/scripts/pages-audit.py를 저장소에서 검토하고 버전 관리한다.
  외부 스킬은 수동 교차 확인에 사용한다. 스킬의 CLI는 탐지 결과가 있어도
  성공 코드로 종료할 수 있어 CI 판정에는 저장소 스크립트를 사용한다.
- Pages 워크플로는 PR과 main 푸시의 빌드에서 정적 파일 전체를 검사한다.
  수동 배포 워크플로는 게시 전 동일 검사를 수행한다. 탐지 결과는 파일,
  줄 번호 및 패턴 이름을 출력한다. 종료 코드 0은 통과, 1은 탐지,
  2는 실행 오류를 의미한다.
- 게시 후 GitHub Actions가 같은 아티팩트를 받아 운영 응답의 바이트,
  HTTPS 리디렉션, HSTS 및 HTML·JS·CSS MIME을 검사한다. Pages에서
  부재가 예상되는 응답 헤더는 기록한다. CDN 전파를 고려해 재시도한다.
  이 단계는 실제 게시 이후 실행되며, 실패 시 진단과 롤백은 운영자가 결정한다.
- 운영 검증에서는 배포 SHA와 GitHub Actions 결과를 확인하고, 실제 승인
  계정으로 로그인부터 콜백까지 실행한다. CSP 위반과 네트워크 오류를
  확인하고 같은 공개 소스 스캔을 다시 실행한다. 실제 키가 확인되면
  새 키 발급, 사용처 교체 및 확인, 기존 키 폐기, 사용 이력 검토를 진행한다.
  알려지지 않은 사용이 확인된 경우 기존 키 폐기를 우선한다.

호스팅 비교
- GitHub Pages. 현재 공개 저장소에서 무료, Actions 및 자동 HTTPS 유지.
  HTML 메타 보호를 적용할 수 있다. 응답 헤더 완전 적용은 불가하다.
  OAuth 주소 변경이 없고 이전 검증 커밋으로 수동 재게시할 수 있다.
- 커스텀 도메인 + CDN. 무료 플랜 범위에서 응답 헤더 규칙을 사용할 수
  있으며 도메인 비용과 DNS 운영이 추가된다. 기존 Actions 게시를 유지하고
  CDN에서 TLS와 CSP, XFO, nosniff를 관리한다. OAuth 반환 URL과 VPS CORS
  출처를 함께 검증한다. 규칙은 개별 롤백할 수 있고 DNS 롤백은 전파가 필요하다.
  헤더 보호 범위는 CDN을 거친 주소다.
  https://developers.cloudflare.com/rules/transform/response-header-modification/
- Cloudflare Pages. 무료 플랜 한도에서 운영할 수 있다. GitHub 연동 또는
  Actions의 사전 빌드 업로드, 관리형 HTTPS, 정적 응답의 _headers,
  이전 배포로 롤백을 지원한다. 새 출처의 OAuth 반환 URL과 VPS CORS,
  Vite base 경로를 검증해야 하며 배포 설정을 관리할 곳이 바뀐다.
  https://developers.cloudflare.com/pages/configuration/headers/
  https://developers.cloudflare.com/pages/platform/limits/
